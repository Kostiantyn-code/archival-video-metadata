# archival-video-metadata

Tools for automated extraction of technical metadata from digital video files for archival description.

Репозитарій містить дві реалізації процесу: Python-сценарії та первинний PowerShell-сценарій.

## Швидкий запуск для колег (Windows)

1. Завантажте репозиторій через **Code → Download ZIP** і **розпакуйте** його в папку, у якій маєте право запису. Не запускайте програму всередині ZIP.
2. Один раз установіть **64-бітний Python** (рекомендовано 3.12 або 3.13) з [python.org](https://www.python.org/downloads/windows/). Увімкніть **Add python.exe to PATH**. Мінімальна версія запуску — 3.10; для встановлення PyAV потрібна доступна готова збірка для вашої версії Python та системи.
3. Покладіть відео в папку **`input`**. Підпапки також обробляються. Підтримуються `.mp4`, `.mov`, `.avi`, `.mpg`, незалежно від регістру розширення.
4. Двічі клацніть **`run.bat`**. Під час першого запуску він створить `.venv` і встановить **PyAV (`av`)** із `requirements.txt`. Для цього потрібен інтернет. Системні пакети Python не змінюються.
5. Відкрийте **`output/run_ДАТА_ЧАС/metadata.csv`**. Кожен запуск створює нову папку з датою, часом та мікросекундами. Попередні результати зберігаються. Якщо є помилки, поруч буде `errors.txt`.

Після успішного встановлення PyAV повторні запуски не потребують інтернету. Окремо встановлювати FFmpeg, ffprobe або компілятор для цього запуску не потрібно: `run.bat` установлює готову бінарну збірку PyAV. Сам Python установлюється один раз вручну.

Вікно не закривається до натискання клавіші, тому підсумок і повідомлення про помилки можна прочитати. Відеофайли відкриваються лише для читання. SHA-256 обчислюється блоками, але потребує прочитати весь файл: для великих колекцій це може тривати довго.

## Відео вже лежать в іншій папці

Копіювати великі файли в `input` не обов’язково. Відкрийте термінал у папці програми та вкажіть свою директорію:

```powershell
.\run.bat --input "D:\Відео архіву"
```

Власна папка звітів і відносні шляхи у першому стовпці CSV:

```powershell
.\run.bat --input "D:\Відео архіву" --output "D:\Звіти" --relative-paths
```

`--relative-paths` корисний, якщо в різних підпапках є однакові назви, наприклад `2025/0001.mp4` і `2026/0001.mp4`. Без цього параметра, як і раніше, записується лише назва файла; програма попередить про її повторення.

Стандартні `input` і `output` визначаються відносно папки програми. Власні відносні шляхи при прямому запуску Python визначаються від поточної робочої папки; `run.bat` спочатку переходить у папку програми. Для зовнішніх директорій зручно використовувати абсолютні шляхи. Папка звітів не може збігатися з вхідною або містити її; якщо вона вкладена у вхідну папку, її пропускають під час пошуку відео.

## Файли та прямий запуск Python

- `run.bat` — рекомендований запуск у Windows з автоматичною підготовкою середовища;
- `input/` — відеофайли та їхні підпапки;
- `output/` — окремі папки результатів;
- `python/archival_video_metadata.py` — основна програма;
- `python/powershell_compatible.py` — той самий механізм обробки з історичним форматом тривалості й розміру;
- `requirements.txt` — залежність PyAV;
- `powershell/resolution3.ps1` — первинний PowerShell-сценарій для довідки; `run.bat` його не використовує.

Для Linux/macOS або ручного запуску у Windows встановіть залежність у власне середовище Python:

```text
python -m pip install --only-binary=:all: -r requirements.txt
python python/archival_video_metadata.py
python python/archival_video_metadata.py --help
```

Після підготовки через `run.bat` для ручного запуску у Windows можна використовувати `.venv\Scripts\python.exe` замість `python`. Сумісний режим підтримує ті самі параметри `--input`, `--output` та `--relative-paths`:

```text
python python/powershell_compatible.py --input "D:\Відео архіву"
```

## Якщо щось не працює

- **Python не знайдено:** установіть Python, увімкніть додавання до PATH і повторіть запуск.
- **PyAV не встановлюється:** перевірте інтернет і текст помилки. Якщо немає сумісної готової збірки, використайте рекомендований 64-бітний Python 3.12 або 3.13. Не потрібно збирати бібліотеку вручну.
- **Папку програми перенесено або Python перевстановлено:** видаліть лише `.venv` і повторіть запуск для відновлення середовища. `input` та `output` видаляти не потрібно.
- **Відеофайлів не знайдено:** перевірте папку і розширення. Порожній CSV у цьому випадку не створюється.
- **Окреме відео не читається:** програма запише помилку в `errors.txt` і продовжить обробку решти. CSV міститиме лише успішні записи.
- **Немає доступу до папки або звіту:** перевірте права запису, вільне місце та вибраний шлях. Помилка запису завершує обробку; вже записані рядки можуть залишитися у частковому звіті.

Коди завершення Python: `0` — успішно або немає відео; `1` — помилка налаштування, залежності чи файлового доступу; `2` — один або більше файлів не оброблено; `130` — перервано через Ctrl+C. Помилкові параметри командного рядка також повертають `2` (стандартна поведінка argparse).

## PowerShell: швидкий запуск у Windows

PowerShell-сценарій безпосередньо використовує **`ffprobe.exe`**, який входить до FFmpeg. Тому для цієї версії **FFmpeg потрібно встановити окремо**.

Цей історичний сценарій має власні жорстко задані шляхи й очікує `ffprobe.exe` за шляхом:

```text
C:\Tools\ffmpeg\bin\ffprobe.exe
```

Якщо FFmpeg установлено в іншому місці, змініть шлях у `powershell/resolution3.ps1`.

Також змініть:

```powershell
$mainDirectory = "d:\temp\2026"
$outputFilePath = "d:\temp\resolution.csv"
```

Запуск із кореня репозитарію:

```powershell
.\powershell\resolution3.ps1
```

Якщо Windows блокує запуск локального сценарію, перевірте політику виконання:

```powershell
Get-ExecutionPolicy
```

Для поточного облікового запису можна дозволити локальні сценарії:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Якщо завантажений файл позначено Windows як зовнішній, його можна розблокувати:

```powershell
Unblock-File .\powershell\resolution3.ps1
```

## Формат результату

Сценарії формують текстові табличні дані для подальшого використання в електронних таблицях.

Основний порядок полів:

1. назва файла або шлях до файла;
2. роздільна здатність;
3. тривалість;
4. розмір файла;
5. SHA-256.

Роздільник полів — **крапка з комою (`;`)**, а дробова частина розміру файла записується з **десятковою комою**. Це зручно для типових українських регіональних налаштувань Windows і Microsoft Excel.

Приклад:

```text
0001.mp4;1920x1080;03:27;31,30;A1B2C3D4...
```

Рекомендований Python-сценарій:

- типово записує лише назву файла; з `--relative-paths` — шлях відносно вхідної папки;
- округлює тривалість до найближчої цілої секунди;
- для записів до однієї години використовує формат `MM:SS`, для довших — `HH:MM:SS`;
- записує розмір із двома знаками після коми;
- подає SHA-256 у верхньому регістрі;
- записує CSV у **UTF-8 with BOM (`utf-8-sig`)**.

Python-сценарій `powershell_compatible.py` зберігає формат, наближений до первинної PowerShell-реалізації: тривалість подається у форматі `MM:SS` із відкиданням дробової частини секунди, причому години не відображаються (наприклад, 3661 с → `01:01`). Для довгих відео рекомендовано основний режим.

PowerShell-сценарій у першому полі записує **повний шлях до файла**, а не лише його назву. Результат записується командою `Out-File -Encoding utf8`; у Windows PowerShell 5.1 це UTF-8 із BOM, у сучасних версіях PowerShell — UTF-8 без BOM.

Якщо Excel не розпізнає структуру автоматично, використайте **Data → From Text/CSV**, вибравши UTF-8 та роздільник `;`.

## Перевірка змін

```text
python -m unittest discover -s tests -v
```

Тести перевіряють формат CSV, контрольну суму, вкладені папки, обидва режими тривалості, обробку пошкоджених файлів і збереження попередніх звітів. Інтеграційний тест створює невелике відео через PyAV. GitHub Actions також запускає `run.bat` на Windows, зокрема з папки з пробілами й кирилицею.
