# Формат вихідних даних

Сценарії репозитарію формують текстові табличні дані, призначені для подальшого використання в електронних таблицях, зокрема Microsoft Excel.

## Роздільник полів і десятковий роздільник

У вихідних файлах як роздільник полів використовується **крапка з комою (`;`)**, а для представлення дробової частини розміру файла — **десяткова кома**.

Такий варіант зручний для типових українських регіональних налаштувань Windows та Microsoft Excel, де кома використовується як десятковий роздільник. Тому рядок результату може мати такий вигляд:

```text
0001.mp4;1920x1080;03:27;31,30;A1B2C3D4...
```

Попри розширення `.csv`, у цьому репозитарії використовується різновид CSV із роздільником `;`, а не комою.

## Поля результату

Основний порядок полів:

1. назва файла або шлях до файла;
2. роздільна здатність відео (`ширинаxвисота`);
3. тривалість;
4. розмір файла;
5. SHA-256.

Поточні сценарії не додають окремого рядка із заголовками колонок.

## Python: рекомендований сценарій

`python/archival_video_metadata.py` формує такі значення:

- **файл** — лише назва файла, без повного шляху;
- **роздільна здатність** — наприклад `1920x1080`;
- **тривалість** — округлюється до найближчої цілої секунди; для записів до однієї години використовується `MM:SS`, для довших — `HH:MM:SS`;
- **розмір** — кількість байтів ділиться на `1024 × 1024`, результат подається з двома знаками після коми, наприклад `31,30`;
- **SHA-256** — шістнадцяткове значення у верхньому регістрі.

Файл записується в кодуванні **UTF-8 with BOM** (`utf-8-sig`). Це полегшує автоматичне розпізнавання UTF-8 програмою Microsoft Excel, зокрема за наявності кириличних назв файлів.

## Python: сумісний сценарій

`python/powershell_compatible.py` зберігає формат, наближений до первинної PowerShell-реалізації:

- записує лише назву файла;
- тривалість подає у форматі `MM:SS` із відкиданням дробової частини секунди;
- розмір округлює до двох знаків і використовує десяткову кому;
- SHA-256 подає у верхньому регістрі;
- використовує роздільник `;` та кодування UTF-8 with BOM (`utf-8-sig`).

## PowerShell-сценарій

`powershell/resolution3.ps1` формує рядок у тому самому загальному порядку, але має кілька відмінностей:

- у першому полі записується **повний шлях до файла**;
- тривалість подається у форматі `MM:SS`;
- розмір округлюється до двох знаків і подається з десятковою комою;
- SHA-256 обчислюється штатною командою `Get-FileHash`;
- поля розділяються крапкою з комою (`;`).

Сценарій записує результат командою `Out-File -Encoding utf8`. Поведінка щодо BOM залежить від версії PowerShell: Windows PowerShell 5.1 створює UTF-8 із BOM, тоді як сучасний PowerShell використовує для значення `utf8` UTF-8 без BOM.

## Відкриття в Microsoft Excel

За типових українських регіональних налаштувань файл із роздільником `;` зазвичай коректно розділяється на колонки. Якщо Excel не розпізнав структуру або кодування автоматично, файл можна імпортувати через **Data → From Text/CSV**, вибравши UTF-8 та роздільник `;`.

Використання крапки з комою як роздільника пов'язане не з українською розкладкою клавіатури, а з регіональними налаштуваннями, за яких кома використовується як десятковий роздільник.
